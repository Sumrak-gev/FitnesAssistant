# Приёмка модуля Профиль ФЗ-05

Разработчик: Денис Столбовой. Ветка: `Drevniy_Jomolungmik`.
Основание: функции ФЗ-05 из ЛР № 1 и уточнённый стек из постановки задачи.

## Соответствие требованиям

| Требование | Реализация |
| --- | --- |
| Личные данные и антропометрия | `UserProfile`, редактор имени, даты рождения, пола, роста, массы и активности |
| Цель и выбранная программа | Общая цель для вкладок «Цели»/«Профиль»; программа из `WorkoutRepository` |
| Хранение между запусками | `ProfileRepository`, Drift, файл `fitness_assistant.sqlite` |
| Настройки уведомлений | Выключены / ежедневно / еженедельно / ежемесячно, время и день |
| Разрешения ОС | Запрос при включении; запрет не скрывается; повторное применение после возврата в приложение |
| Правовой блок | Соглашение, конфиденциальность, риски тренировок, сведения о приложении |
| Ошибки ввода и сохранения | Валидация всей формы, переход к ошибке, сообщения при проблеме БД или планировщика |

- 20 тестов Flutter: повторное открытие файловой SQLite, обновление единственной
  записи, очистка необязательных полей, недопустимые значения, общая цель,
  редактирование, десятичная запятая, валидация полей вне видимой области,
  правовые экраны, расписания и обработка разрешений.
- Вызовы плагинов Android/iOS проверены через подмену platform channels:
  периодичность, часовой пояс, один ID, отмена, запрет разрешения,
  отсутствие автоматического запроса разрешения при запуске.
- Проверены переход года, февраль и переход на летнее время.
- 8 тестов pytest: liveness/readiness, сокрытие подробностей ошибки БД,
  OpenAPI, настройки драйвера, сокрытие секрета в repr и компиляция моделей PostgreSQL.
- `alembic upgrade head --sql` успешно формирует SQL первой миграции.

## Проверка на Android и iOS

Эти сценарии требуют реальных устройств или эмуляторов и пока не выполнены.
Подмена platform channels не подтверждает фактическую доставку уведомлений.

1. Запустить приложение без интернета. Открыть «Профиль», заполнить имя, дату
   рождения, пол, рост, вес, активность, цель, целевой вес и программу. Сохранить.
2. Полностью закрыть и вновь открыть приложение. Убедиться, что поля сохранились.
3. Выбрать другую цель на вкладке «Цели». Проверить её в профиле и после перезапуска.
4. Ввести пустое имя, отрицательный вес, текст вместо числа. Сохранение должно быть
   отклонено. Значение `82,5` должно сохраняться как 82.5 кг.
5. Очистить целевой вес, выбрать «Не выбрана» для программы; сохранить и перезапустить.
6. Включить ежедневное напоминание на ближайшее время. Разрешить уведомления и
   проверить доставку в фоне. Повторить для еженедельного и ежемесячного режима.
7. Запретить уведомления в системе. Приложение должно показать причину отсутствия
   напоминаний. Разрешить их и вернуться: расписание должно восстановиться.
8. Отключить уведомления. Убедиться, что запланированное уведомление больше не приходит.
   На Android дополнительно проверить восстановление после перезагрузки телефона.
9. Сменить часовой пояс, открыть приложение и проверить время следующего напоминания.
10. Открыть все четыре информационных экрана; проверить прокрутку и увеличенный шрифт.

Android использует неточные будильники: система может задерживать доставку.
Ежемесячно выбираются дни 1–28, чтобы дата существовала в любом месяце.

## Границы готовности

Android APK и iOS-сборка в текущем окружении не проверены: Android SDK и Xcode
недоступны. Локальный сервер PostgreSQL 18 не настроен; миграция к реальной БД
не применялась. Для проверки схемы на отдельной `fitness_test` нужны
`alembic upgrade head` и `alembic check`.

Авторизация и синхронизация остаются следующими этапами. Модули питания,
тренировок и прогресса не реализовывались в рамках работы над ФЗ-05.
Правовые тексты относятся к учебному прототипу; сведения об ответственном и
контакты необходимо добавить перед публичным выпуском.
