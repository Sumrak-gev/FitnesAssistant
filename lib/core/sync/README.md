# Синхронизация

`SyncWriter` записывает сущность и outbox одной транзакцией Drift.
`SyncEngine` сначала получает журнал, затем отправляет операции в порядке sequence,
подтверждает конкретный mutationId, обновляет serverVersion и baseVersion последующих
локальных правок. Новые правки во время отправки не удаляются подтверждением старой.

Pull хранит серверную версию в локальном inbox (AppSettings remote:entity:id).
Пока у сущности есть outbox, pull не перезаписывает её. Подписанный сервером курсор
сохраняется в той же транзакции, что inbox/применение изменений. Push-cursor не подменяет pull-cursor.
Повтор после потерянного ответа сохраняет прежний ключ идемпотентности.
Локальные слоты питания совпадающего дня/типа приводятся к серверному UUID вместе с FK и очередью.

409 останавливает отправку. Пользователь выбирает локальную версию (если серверная запись
существует и не удалена) либо серверную; при отсутствии серверной записи выбранное отклонённое
локальное изменение мягко удаляется. Ошибка сети сохраняет очередь и повторяется с задержкой
до 5 минут. Foreground и Android WorkManager используют общую SQLite lease; refresh защищён
отдельной lease, чтобы конкурентное обновление не отзывалo корректную сессию.

Профиль/цели/программы/прогресс/достижения используют FitnessRecords с проверяемыми DTO на сервере.
КБЖУ сохраняет специализированные таблицы и составные FK. Для нового модуля:
1. Добавьте проверяемый DTO и entity в серверный discriminated union.
2. Сохраняйте через FitnessRepository.save или новую таблицу с SyncMetadata и SyncWriter.
3. Добавьте применение pull, миграцию при изменении схемы и тест повторного обмена.
Имена nutrition_users/nutrition_outbox оставлены для обновления существующих установок.
