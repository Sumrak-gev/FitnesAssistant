# Фитнес-помощник

Flutter-приложение для Android: профиль, цели, дневник КБЖУ, тренировки и прогресс.
Версия 0.3.0 остаётся pre-alpha до проверки на физическом Android-устройстве и настоящем HTTPS-домене.
Локальные результаты и непроверенные сценарии перечислены в [проверке 0.3.0](docs/verification-0.3.0.md).
Локальные данные хранятся в Drift (схема v4), сервер — FastAPI/PostgreSQL 18.
Исходная основа этой версии — `main`, рабочая ветка — `Drevniy_Jomolungmik`.

## Что работает

- Регистрация и вход по email; отображаемое имя не используется для входа.
- Argon2id, access JWT на 15 минут, refresh на 30 дней. Refresh хранится на сервере только как SHA-256,
  ротируется при обновлении; повторное использование отзывает семейство и его access-токены.
- Первый вход требует сети. После регистрации пользователь выбирает цель; позже она меняется в настройках.
  После входа дневник и остальные разделы доступны офлайн.
- Профиль, цели, продукты, приёмы пищи, порции, программы тренировок и отметки прогресса
  сохраняются в Drift и общей очереди. Перезапуск не теряет изменения.
- Четыре основных раздела: КБЖУ, тренировки, прогресс и настройки. В настройках есть выбор
  светлой, тёмной или системной темы и бело-синей либо мятной палитры. Бело-синюю палитру
  обозначает небольшой флаг Израиля. Уровень показывает опыт за тренировки, дни в норме калорий
  и завершённые недели. Отдельного раздела достижений больше нет; старые серверные записи
  пока принимаются для совместимости прежних клиентов.
- Шкала прогресса состоит из десяти уровней: 1–5 — «Мистер ЧМО», с 6-го — «Силач».
  Оба этапа оформлены трафаретными портретами по пользовательским фотографиям;
  на груди силача — цветная звезда Давида.
  После 10-го уровень остаётся максимальным, накопленный XP продолжает отображаться.
  На 6-м уровне открывается карточка со ссылкой на сторонний Telegram-канал
  помощи с получением паспорта Израиля.
- Пользователь может собрать свой план тренировок из локального каталога упражнений.
- Push/pull с идемпотентностью, серверными версиями, tombstones, курсорами и изоляцией пользователей.
  Конфликт 409 требует выбора версии в интерфейсе; удалённая сервером запись не восстанавливается молча.
- Отправка при изменениях, возврате в приложение и периодические повторы с задержкой.
  Android WorkManager запускает отдельную фоновую задачу при доступной сети; период от 15 минут,
  фактическое время определяет ОС. SQLite leases исключают одновременную отправку и ротацию токенов
  основным и фоновым Flutter engine.
- Продукты и упражнения загружаются из серверного каталога и сохраняются для работы офлайн.
  Серверные импортеры: Open Food Facts и free-exercise-db. Телефон обращается только к нашему API.
- Локальные уведомления с запросом разрешения Android 13+ при включении. Расписание неточное
  (`inexactAllowWhileIdle`), поэтому разрешение точных будильников не требуется.

Одна установка привязывает локальную БД к одному аккаунту. Выход скрывает локальные данные за экраном входа,
но не удаляет их. Вход другим аккаунтом отклоняется, чтобы не смешивать дневники.
Локальный `nutrition_users.id` сохраняется; соответствие серверному UUID хранится в `AppSettings.accountId`.
Авторизацию на сервере определяет исключительно JWT, а не это локальное соответствие.

## Запуск сервера

Нужны Python 3.12 и PostgreSQL 18 либо Docker Compose.

1. Скопируйте `server/.env.example` в `server/.env`. Сгенерируйте **разные** пароли администратора,
   миграционной роли и приложения. Для DSN в Compose используйте hex-пароли без специальных символов.
   Например, `python -c "import secrets; print(secrets.token_hex(32))"`; для JWT — `token_hex(48)`.
2. Для локального PostgreSQL создайте отдельные роли/БД по образцу `server/deploy/init-roles.sh`.
   Миграции запускайте владельцем схемы, API — ролью `fitness_app` без SUPERUSER, CREATEDB и CREATEROLE.
   Не открывайте порт PostgreSQL в интернет.
3. Из корня репозитория:

```sh
python -m venv .venv
# Активируйте .venv средствами вашей ОС
pip install -r server/requirements.txt
cd server
# DATABASE_URL на время миграции — DSN владельца схемы
alembic upgrade head
# Верните DATABASE_URL роли fitness_app перед запуском API
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Единственный источник схемы — последовательность Alembic `0001 → 0002 → 0003`.
Дублирующий `app/models.py` удалён; модели регистрируются пакетом `app/models/`.
Если старая БД создавалась вручную, сначала сделайте backup и сравните схему; не выполняйте
`alembic stamp` для неизвестной схемы. Миграция v3 добавляет в журнал уже существовавший дневник.

Вариант с Compose (пароли и JWT читаются из `server/.env`):

```sh
docker compose --env-file server/.env up --build -d db migrate api
```

API публикуется только на `127.0.0.1:8000`; PostgreSQL не публикует порт.
Проверки: `GET /health`, `GET /health/db`; документация: `/docs`.

## Запуск Android

Версия Flutter в CI: 3.47.5; `pubspec.yaml` требует Flutter не ниже 3.47.5.
Локальный прогон предыдущей версии выполнялся на Flutter 3.47.7. Нужны Android SDK и JDK 21
для текущих Gradle/AGP. Минимальная версия приложения — Android 7.0 (API 24).

При проблемах генерации из Windows-пути с кириллицей можно открыть проект через свободный
виртуальный диск (PowerShell из корня репозитория; после перезагрузки повторите subst):

```powershell
$fitnessProjectPath = (Get-Location).Path
subst R: $fitnessProjectPath
Set-Location R:\
```

```sh
flutter pub get
dart run build_runner build
flutter run --dart-define=API_URL=http://10.0.2.2:8000
# Альтернатива: flutter run --dart-define-from-file=.env.example
```

`10.0.2.2` — адрес хоста из Android-эмулятора. Для USB-устройства можно выполнить
`adb reverse tcp:8000 tcp:8000` и задать `http://127.0.0.1:8000`.
HTTP разрешён только в debug и только для адресов из
`android/app/src/debug/res/xml/debug_network_security_config.xml`.
Для LAN внесите конкретный отладочный адрес в этот файл; release допускает HTTPS.

В первый запуск создайте аккаунт и выберите цель. Позже цель меняется в «Настройках».
Каталог продуктов: вкладка КБЖУ → значок продуктов →
«Загрузить из каталога» (учитывается строка поиска, до 100 результатов за запрос).
Тренировки: «Загрузить каталог упражнений». До серверного импорта каталоги пусты; можно вручную
добавлять продукты, а для тренировок в БД один раз сохраняется небольшой стартовый набор.
Кнопка «Свой план» позволяет выбрать упражнения и сохранить собственную программу офлайн.

## Импорт открытых каталогов

Выполняется администратором сервера, независимо от запросов поиска телефона:

```sh
cd server
python -m app.import_catalogs off --pages 3 --user-agent "FitnessAssistant/0.2.0 (maintainer: YOUR_CONTACT)"
python -m app.import_catalogs exercises --user-agent "FitnessAssistant/0.2.0 (maintainer: YOUR_CONTACT)"
# Повторяемый импорт из сохранённого снимка:
python -m app.import_catalogs off --file products.json
python -m app.import_catalogs exercises --file exercises.json
```

OFF: структурированный поиск v2 по стране `en:russia`, до 100 продуктов на страницу,
пауза между страницами, неполные/некорректные значения пропускаются.
UUID источников стабильны, повторный импорт обновляет серверный каталог без дублей.
Пользовательские снимки порций и отредактированные продукты автоматически не перезаписываются.
Для упражнений используется free-exercise-db (английские названия, переведены группы мышц/оборудование),
без утверждения об известных противопоказаниях.

Источники и атрибуция:
[Open Food Facts](https://world.openfoodfacts.org/) —
[ODbL и Database Contents License](https://openfoodfacts.github.io/openfoodfacts-server/api/tutorials/license-be-on-the-legal-side/);
[free-exercise-db](https://github.com/yuhonas/free-exercise-db) —
[The Unlicense](https://github.com/yuhonas/free-exercise-db/blob/main/LICENSE.md).
Сведения показаны также в «О приложении». Изображения источников не импортируются.
Производный каталог OFF хранится отдельно от личных дневников. Оператор должен предоставлять
его на условиях ODbL; экспорт только каталога: `python -m app.export_catalog > products-export.json`.

## HTTPS, роли и резервные копии

Для своего VPS настройте DNS `API_DOMAIN` на сервер, откройте только 80/443 и SSH по своей политике.
Заполните секреты и запустите:

```sh
docker compose --env-file server/.env --profile production up --build -d
```

Caddy получает/обновляет сертификат, nginx ограничивает частоту запросов (отдельно `/auth/*`).
В Compose Caddy имеет адрес `172.30.40.11`, nginx — `172.30.40.10` в закрытой сети edge:
nginx доверяет forwarded IP только Caddy, Uvicorn — только nginx. API считает неудачные попытки
по IP и email/device ID в одном процессе; успешные входы эту квоту не расходуют.
Общий nginx-лимит охватывает любой auth-запрос. Compose запускает один worker.
Перед публикацией проверьте эту цепочку на реальном стенде с разных клиентских IP; при смене
подсети согласованно обновите Compose, nginx и `FORWARDED_ALLOW_IPS`.
CORS по умолчанию запрещает все browser origins; для нужного веб-клиента задайте JSON-список
`CORS_ORIGINS`. CORS не заменяет аутентификацию мобильного API.
Пароли, входные тела валидационных ошибок и строки подключения не возвращаются клиенту.
Образы используют плавающие minor-теги: перед публичным развёртыванием зафиксируйте проверенные digest.

Миграции выполняются отдельной ролью `fitness_owner`; приложение не получает права менять схему.
Инициализатор ролей работает только на новом PostgreSQL volume. Для существующей БД выдайте
права явно; не удаляйте volume ради переинициализации.

Сервис `backup` делает `pg_dump -Fc` при старте и каждые 24 часа, проверяет структуру архива
и хранит 14 дней в Docker volume `backups`. Для локального стека: `--profile backup`.
Копируйте архивы на отдельный носитель/хост с ограниченным доступом. Для проверки восстановления
создайте отдельную БД владельцем схемы и выполните `pg_restore --no-owner --no-acl -d NEW_TEST_DB archive.dump`;
затем проверьте health, вход и дневник. Не проверяйте restore на рабочей БД.

## Подпись release

Application ID: `ru.fitnesassistant.app`, версия: `0.3.0+3`, своя иконка.
Скопируйте `android/key.properties.example` в `android/key.properties`, укажите свой приватный keystore.
Без него release-сборка завершается ошибкой; автоматической подписи debug-ключом нет.

```sh
flutter build appbundle --release --obfuscate --split-debug-info=build/symbols --dart-define=API_URL=https://YOUR_API_DOMAIN
```

R8 и сокращение ресурсов включены. Храните keystore, пароли и symbols отдельно от Git и резервируйте их.
iOS оставлен в репозитории; фоновая синхронизация в этой версии настроена только для Android.
Условия использования описывают учебный проект; перед публичным выпуском нужны реальные сведения
об операторе, контакты и процедура удаления серверного аккаунта.

## Проверки

```sh
cd server
# Только отдельная PostgreSQL fitness_test, уже обновлённая миграциями:
# задайте TEST_DATABASE_URL и DATABASE_URL
python -m pytest -q
alembic check
uvicorn app.main:app --host 127.0.0.1 --port 8000
# В другом терминале из корня:
flutter analyze
flutter test
# Для полного обмена с настоящим API задайте TEST_API_URL=http://127.0.0.1:8000
flutter test test/sync_integration_test.dart
```

В PowerShell переменные задаются как `$env:TEST_API_URL='http://127.0.0.1:8000'`.
Без TEST_API_URL только сетевой интеграционный тест пропускается; остальные выполняются.
Тестовый API должен использовать исключительно `fitness_test`.

Покрыты auth, хеши, ротация/replay/logout, истечение access, изоляция владельцев и FK,
идемпотентность, откат пакета, версии, курсоры, пагинация, ограничения и сериализация.
Интеграционный Flutter-тест: запись в Drift до входа → API → вторая Drift БД, потеря ответа после commit,
конфликт и выбор версии, объединение приёма пищи с двух устройств. CI повторяет анализ, тесты и debug APK.
Проверки реального устройства, системного фонового планировщика и production HTTPS описаны
в [приёмке Android](docs/github-prealpha-release.md).
Проверки версии 0.2.0 сохранены как [исторический отчёт](docs/verification-0.2.0.md).
Текущий выпуск остаётся pre-alpha, пока не пройдена ручная проверка на устройстве.
