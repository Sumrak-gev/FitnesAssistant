# Фитнес-Ассистент

Учебное мобильное приложение для Android и iOS. Ветка `CPFC` содержит готовый локальный модуль КБЖУ и интегрированную основу
профиля, уведомлений и серверной БД из `Drevniy_Jomolungmik`.
Тренировки и достижения сохранены в состоянии исходного каркаса команды.

## КБЖУ

- Каталог продуктов: создание, поиск, редактирование и мягкое удаление.
- Пищевая ценность на 100 г, порции в граммах, ввод дробей с точкой или запятой.
- Дневник по датам: завтрак, обед, ужин и перекус; изменение порции, даты и приёма пищи,
  удаление записи или всего приёма пищи.
- Итоги КБЖУ за день и календарную неделю с понедельника по воскресенье.
- Расчёт ориентировочной нормы по фактическим данным профиля и цели; прогресс
  по каждому показателю, остаток/превышение и процент выполнения.
- Снимки пищевой ценности в дневнике: правка каталога не меняет прошлые записи.
- Drift схема 2 с миграцией из схемы 1, PostgreSQL Alembic `0002_nutrition`,
  репозитории с проверкой владельца, индексы, ограничения и очередь изменений.
- Типизированные Dart/Pydantic DTO и [OpenAPI-контракт](docs/nutrition-openapi.json).
  Сетевой транспорт синхронизации и авторизация остаются следующим этапом.

## Архитектура и стек

Модульный монолит: клиент и сервер находятся в одном GitHub-репозитории.

| Часть | Технологии и состояние |
| --- | --- |
| Клиент | Flutter / Dart, Material 3, Provider |
| Локальная БД | SQLite через Drift, профиль и питание работают без интернета |
| Уведомления | flutter_local_notifications, локальный часовой пояс устройства |
| Сервер | Python, FastAPI, Uvicorn, Pydantic; `/docs`, `/health`, `/health/db` |
| Серверная БД | PostgreSQL 18, отдельные `fitness_dev` и `fitness_test`; это не реплики |
| Доступ к БД | SQLAlchemy 2, psycopg 3, миграции Alembic |
| Авторизация — план | Email, Argon2id, JWT access и refresh-токены; секреты в `.env` вне Git |
| Синхронизация — план | Flutter ↔ API ↔ PostgreSQL, локальная очередь изменений, push/pull |
| Тесты | flutter_test; pytest + httpx |

Уточнённый стек из постановки задачи расширяет локальную архитектуру ЛР № 1.
Исходная `CPFC` (`16d9e4d`) не содержала серверного каталога; общая основа
и первая миграция перенесены из предыдущей работы над профилем. Наличие миграции в Git не означает, что она уже
применена к БД на чьём-либо ПК. Перед объединением с серверной работой команды
необходимо согласовать историю Alembic; не применять две независимые первые миграции.

## Что реализовано в ФЗ-05

- Локальный профиль: имя, дата рождения, пол, рост, масса тела и активность.
- Фитнес-цель, необязательный целевой вес и программа из существующего каталога.
- Общая цель для вкладок «Цели» и «Профиль», сохранение между запусками.
- Проверка пустого имени, даты, конечных чисел и диапазонов; ввод дробей с точкой или запятой.
- Напоминания выключены по умолчанию. Доступны ежедневный, еженедельный и
  ежемесячный режимы, выбор времени, дня недели и дня месяца (1–28).
- Запрос разрешения только при включении; сообщение при запрете или ошибке ОС;
  отмена при отключении; восстановление расписания при запуске/возврате в приложение.
- Соглашение, политика конфиденциальности, сведения о приложении и предупреждение о рисках.

Профиль не отправляется на сервер. API входа, JWT, Argon2id и синхронизация пока
не реализованы. Модели `users`, `devices`, `refresh_tokens` — серверная основа авторизации.
Таблицы `nutrition_products`, `nutrition_meals`, `nutrition_entries` и их
репозитории реализованы; клиент использует локальную БД до подключения синхронизации.
Тексты правовых экранов описывают учебный прототип; перед публичным выпуском
нужно указать ответственных и контакты и актуализировать условия.

## Структура

```text
lib/
  core/db/       # Drift, схема 2 и сгенерированные типы
  core/api/      # место общего API-клиента, следующий этап
  core/auth/     # план авторизации
  core/sync/     # план синхронизации
  models/        # модели профиля, настроек и существующих модулей
  data/          # ProfileRepository и каталоги команды
  services/      # ProfileController, планировщик напоминаний
  screens/profile/ # профиль, редактор, уведомления, правовые экраны
server/
  app/           # FastAPI, настройки, SQLAlchemy
  alembic/       # миграции PostgreSQL
  tests/         # проверки API и конфигурации
test/            # проверки Flutter, SQLite и расписаний
docs/            # сценарии приёмки ФЗ-05
```

## Запуск клиента

Flutter SDK устанавливается отдельно. Проверенная версия SDK фиксируется в
`docs/profile-acceptance.md`; Dart должен быть не ниже 3.12. Android: API 24+;
iOS: 15+ (настройка исходного проекта). Сборка iOS требует macOS/Xcode.

```sh
flutter pub get
dart run build_runner build
flutter analyze
flutter test
flutter run
```

Сгенерированный файл Drift включён в Git. После изменения таблиц обновляйте
генерацию, увеличивайте версию схемы и добавляйте миграцию с тестом сохранности данных.
Данные лежат в `fitness_assistant.sqlite` в каталоге документов приложения.
Старый sqflite-код в исходной ветке отсутствовал, переноса существующей БД не требуется.

Android использует неточные системные напоминания без разрешения на точные будильники.
ОС может задерживать доставку из-за энергосбережения. После смены часового пояса
откройте приложение. Разрешения и фактическую доставку нужно проверять на устройствах.

## Запуск сервера

Python 3.11+. Команды выполняются из `server/`:

```sh
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
python -m pip install -e ".[test]"
```

В локальном PostgreSQL 18 создайте роль `fitness_app` с собственным паролем и две
отдельные пустые базы `fitness_dev` и `fitness_test`, принадлежащие этой роли.
Скопируйте `.env.example` в `.env`, замените `CHANGE_ME`. Реальные секреты не коммитить.

```sh
alembic upgrade head
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Документация: `http://127.0.0.1:8000/docs`. `/health` проверяет процесс без БД,
`/health/db` проверяет соединение и возвращает 503 при недоступной БД.
Клиентский профиль не зависит от запущенного сервера.

```sh
python -m pytest -q
alembic upgrade head --sql
```

Для интеграционных тестов задайте `TEST_DATABASE_URL` на отдельную PostgreSQL 18
базу с именем **fitness_test**. Примените к ней миграции, временно задав тот же URL
в `DATABASE_URL`, затем выполните `alembic check` и `python -m pytest -q`.
Тесты отказываются работать с другой БД. Без `TEST_DATABASE_URL` интеграционные
проверки пропускаются; остальные тесты не требуют запущенной БД.
Не запускайте `downgrade` на базе с нужными данными.
